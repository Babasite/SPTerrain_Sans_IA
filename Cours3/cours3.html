Outils: SQL, Excel, Power BI, Tableau, Python

SGBD (système de gestion de bdd) Prérequis Commandes ds terminal

Pr faire une requête SQL, il faut un logiciel "SGBD" (MySQL) -> MariaDB (“copie” open-source de MySQL). Installer MySQL sur ordi Ici

Ds la ligne de commande: -u (pr donner utilisateur), -p (pr rentrer le MP), create database (pr créer la BDD), show database (pr vérifier), use.

On utilisera CRUB (voire Cours 2), On ajoute objet à une table avec commande INSERT INTO.
Objets se lisent avec commande SELECT FROM.
Mettre à jour objets d’une table avec UPDATE (on mentionne quelles sont colonnes qu’on souhaite mettre à jour avec SET).
Pour spécifier objets qu'on souhaite modifier, on ajoute condition WHERE (si on filtre pas avec WHERE, on risque mettre à jour ts les objets de la table).
On supprime objets d’une table avec DELETE. (si on filtre pas avec WHERE, on risque supprimer ts les objets de la table).
On peut supprimer une table ou une base de donnée avec DROP TABLE ou DROP DATABASE.

Pour filtrer sur des données numériques on utilise le mot clé WHERE.
S'utilise invariablement avec SELECT , UDPATE , DELETE. Supporte tous les opérateurs de comparaison comme = , <, <=, > ou >= .
Pour les données textuelles, on utilise LIKE.
Utiliser pourcentage (%) pr affiner recherche
(%gmail.com -> txte se terminant par gmail.com, gmail.com% -> txtes commencant par gmail.com, %gmail.com% -> texte contenant gmail.com au début ou à la fin).
Ordonner les résultats d’une requête SQL avec la commande ORDER BY.

Possible compter nbre de lignes d'une requête grâce à fonction COUNT.
Pour identifier doublons, utiliser fonct COUNT combinée à fonct DISTINCT.
Utiliser des "alias" grâce au mot clé AS (pr renommer variables ou colonnes).
SQL propose une très grande variété de foncts pr nbres, txtes ou dates:
AVG: Donne moyenne colonne sur la sélection ;
SUM: Donne somme colonne;
MAX: Donne le maximum de la colonne sur la sélection;
MIN: Donne minimum colonne.

Sauvegarder des requêtes complexes, longues ou utilisées svt.
Concept de "vue" crée grâce à CREATE VIEW (commande peut être longue, pas hésiter pas à sauter des lignes, mettre des parenthèses et des indentations pour la rendre lisible).
Par convention on note ces vues avec "_vw" à la fin (pr les différencier des "vraies" tables). Une fois créée, une vue s'utilise comme une table "normale".

Pour effectuer jointure entre deux tables, mots clés JOIN et ON .
On peut utiliser opérateur * ou spécifier colonnes que nous souhaitons sélectionner.
La requête fonctionne comme une requête normale, on peut rajouter des conditions avec WHERE , trier avec ORDER BY ou créer des alias avec AS.
Pour relation one-to-many, jointure se fait en spécifiant les deux colonnes à faire correspondre (passer par une table d'association qui lie les deux tables entre elles).
Pr faire requête many-to-many, on fait donc double jointure de table initiale à table de liaison, puis de table de liaison à table cible.

Tte modification structure d’un objet s’effectue avec ALTER TABLE.
Pr ajouter un champ à un objet, utiliser le mot clé ADD. Pr supprimer un champ, le mot clé est DROP. Pour modifier un champ, le mot clé est MODIFY pr en modifier la structure, CHANGE pr le renommer. Attention qd on utilise la commande ALTER TABLE , bien réfléchir aux conséquences des modifications.

Ajouter une table est relativement facile, mais la lier à d'autres plus de travail.
Créer nvelle table (et ajouter des objets dedans), créer ce qui se qui sera la clé de jointure ds table initiale,
préciser à MySQL "lien" entre clé étrangère (de table initiale) et nvelle table.
Attention à l'attribut ON DELETE (qui précise quoi faire sur table initiale) si on supprime un objet de table de destination.
Mettre à jour valeurs table initiale (afin pouvoir faire requêtes en joignant les deux tables).
Pour modéliser une relation plsrs à plusieurs, besoin créer une table d'association. (qui contient deux FOREIGN KEY qui sont des PRIMARY KEY ds leurs tables respectives).
Ces deux FOREIGN KEY st la PRIMARY KEY de table d'association. Être attentif au paramètre ON UPDATE qui doit être cohérent avec les paramètres ON DELETE des tables concernées.
